# Environment variables

cheap-mem is configured mostly by files, but a few dozen behaviours also
answer to an environment variable: a hook that is switched off for one session, a
search lane that is opt-in, a server that binds somewhere else. They were scattered
over the code until `src/envregister.mjs` gathered them into one register.

Two guards keep this page and the code from drifting apart (`test/envregister.test.mjs`):

- Every environment variable read in `src/`, `bin/`, `install/` or `hooks/` has a
  row in the register, and every row is still read somewhere. A new read without a
  row turns the test red; so does a row nobody reads any more. Standard variables
  of the operating system (`HOME`, `PATH`, `TMPDIR`, ...) are not registered.
- The table below is generated from the register. The test compares it with
  `renderTable()`; after a change, `node bin/mem envvars --markdown` prints the
  new block to paste between the two marker lines.

`mem envvars [--json]` prints the same register from the command line, with the
value each variable has in the current environment (secrets are shown as `set`
or `not set`, never as a value).

A variable that is not in the table is not a switch: there is none.

### Switches — they change what happens

| Variable | Default | Meaning |
| --- | --- | --- |
| `CHEAP_MEM_CALENDAR_ROUTE` | not set (no outside calendar) | Which route puts an appointment into a real calendar: SMTP invitation or the Google Calendar API. |
| `CHEAP_MEM_CARD_REJECT` | off (stage 1: warn and mark) | Stage 2 of the decision-card rule (H11): with `yes` (also `true`, `1`; `no`, `false`, `0` are off) a NEW duty or question addressed to the human participant WITHOUT a complete decision card (`card_question`, at least two `card_options`, one of them a No / not-now option) is refused and nothing is written. Without it the entry is taken in, the writer is warned loudly and the entry shows as "explanation missing" (a fallback card; the doctor finding `decision-without-explanation` counts it). Applies on the free input roads only (`mem log`, `mem correction`, `mem restore`, `mem questions new`, the bridge `mem_log`); internal writers are never refused. Any other value is reported once per process and counts as off. |
| `CHEAP_MEM_JSONL_APPROVAL` | not set (the pre-commit hook refuses any changed or deleted committed log line) | AU11: lets ONE commit change or delete committed lines of a memory log (a real redaction, an entry moved to another drawer). The value is the reason and the approval id; the hook names it and the files in the log. Set it inline before `git commit`, never export it. |
| `CHEAP_MEM_MAX_AUTHORITY` | not set (no ceiling; the digest sets `inferred`) | The highest authority a process may claim in what it writes. A model-backed writer must never produce a `user` entry; the digest and the reflector run under a lower ceiling. |
| `CHEAP_MEM_MCP_DECRYPT` | off (the bridge shows encrypted entries as unreadable) | With `1` the MCP bridge decrypts entries written with `shred` for the agents connected to it. The keyring sits beside the data, so without this a connected foreign agent could read what a clone of the git data cannot. |
| `CHEAP_MEM_MCP_READONLY` | off (full tool profile) | With `1` the MCP bridge offers only the read tools. |
| `CHEAP_MEM_PROFILE` | off | With `1` the hooks write a profile of where their time went. |
| `CHEAP_MEM_QUESTION_TEXT` | on | With `off` (also `0`, `no`, `false`) the wording of recall questions is no longer kept in `<root>/.mem/local/question-text/` (redacted, git-ignored, 30 days; for the reverse test and the search guard G7). The recall journal never holds the wording either way. |
| `CHEAP_MEM_SERVE_BEHIND_TUNNEL` | off | With `1` the viewer trusts `CF-Connecting-IP` from a loopback connection as the source of a sign-in attempt (a tunnel on this machine). Without it the socket address counts. |
| `CHEAP_MEM_SERVE_LOGIN` | on | With `off` the viewer's login is skipped (tests, local only). |
| `CHEAP_MEM_SERVE_OFFLINE` | off | With `1` the viewer loads nothing from outside. |
| `CHEAP_MEM_SERVE_READONLY` | off | With `1` the viewer shows everything and sets nothing. |
| `CHEAP_MEM_SERVE_SERVICE` | not set | Installer: whether to register the viewer as a service (`1`/`yes`). |
| `MEM_AFTER_FAILURE_OFF` | off | The after-failure hook (what the memory knows about a command that just failed) is switched off by `1` |
| `MEM_ANSWER_CHECK` | on | With `0` the stop-time answer check never blocks a turn. |
| `MEM_BEFORE_EDIT_OFF` | off | The before-edit hook (what the memory knows about a file about to change) is switched off by `1` |
| `MEM_BROADCAST_OFF` | off (a new error entry is broadcast) | With `1` `mem log error` does not broadcast the new error to the other sessions. |
| `MEM_CAPTURE_OFF` | off | The raw capture of a session transcript is switched off by `1` |
| `MEM_CATCH_FAIL_OFF` | off | The swallowed-failure hook is switched off by `1` |
| `MEM_CLONE_GATE` | on | With `0` the recall hook never adds the "which clone answered" line when the clone is stale (src/clonegate.mjs). |
| `MEM_CLOSING_REPORT` | on | With `0` the closing report of open duties is not shown. |
| `MEM_CORRECTION_WARN_OFF` | off | With `1` `mem correction` does not warn when a rare word of the old entry is missing from the correction. |
| `MEM_EXPAND` | off | With `1` the search also reads the `asked_as` phrasings stored next to an entry (document expansion, weight 0.3). Off, the search is bit-identical to before. |
| `MEM_GOLD_DAILY` | yes | With `no` the digest does not run the daily gold-miss collection. |
| `MEM_HEADLESS` | not set | Marks an unattended run (the digest, the reflector, any `claude -p` worker); its value names the run. Such a run is not captured, writes with a lowered authority, may not confirm projects, categories, appointments or mail permits, and never writes a line of tier `user` (refused in the write core). |
| `MEM_HOOK_OFF` | off (all hook stages active) | Emergency stop for the whole hook chain in one session: every hook stage is switched off by `1`. A session without hooks has no memory. |
| `MEM_RAW_EXCLUDE` | off | With `1` the raw capture skips the session (the environment form of the exclude mark). |
| `MEM_RECALL_SERVER` | on (the hook asks the warm server when its socket exists) | With `0` the recall hook never asks the warm recall server and always searches directly. |
| `MEM_REFLECT` | off (opt-in) | With `1` the stop hook starts the model-backed reflector. |
| `MEM_RETRIEVE_NO_PULL` | off (the hook pulls when the clone is older than `MEM_RETRIEVE_FRESH_MIN`) | With `1` the recall hook never runs `git pull` first. |
| `MEM_RETRIEVE_OFF` | off | The recall hook (the relevant entries shown on a question) is switched off by `1` |
| `MEM_RETRIEVE_REQUEST_FRAME` | on (`0` switches it off) | With `0` the request frame at the start of a question ("explain", "can you show me") is searched like every other word, in the recall hook and in the content-word query. |
| `MEM_REWRITES` | on (the table ships empty) | `off` switches the whole query-rewrite table off. |
| `MEM_RULE_DRAFT` | on (`no` switches it off) | AU6: with `no` the digest tick does not write the weekly rule drafts (thoughts tagged `rule-proposal`, at most one per error class and week). |
| `MEM_SEARCH_LEVERS` | the levers' own defaults | `off`, `all` or a list such as `h1,h3`: which Block H search levers are on (`mem search-levers`). |
| `MEM_SKILL_ACCOUNT_OFFER` | on (`0` switches it off) | With `0` a skill offer no longer brings the two most important lines of the skill's experience account. |
| `MEM_SKIP_DIGEST` | off | Windows installer: with `1` the digest task is not registered. |
| `MEM_SOLUTION_ATTACH` | on (`0` switches it off) | With `0` the recall hooks no longer put the newest valid solution (a `resolves` link) as one line under a shown error. |
| `MEM_STOP_NO_PUSH` | off (the stop hook commits and pushes) | With `1` the stop hook does not push. |
| `MEM_SUBAGENT_START_OFF` | off | The sub-agent start hook is switched off by `1` |
| `MEM_SUBAGENT_TASK_OFF` | off | With `1` the sub-agent start no longer adds the block for the assignment (errors, learnings, duties, procedures, skills that fit the task); the base block stays. |
| `MEM_WATCH_APPOINTMENTS` | on (when an appointments file exists) | With `off` the watcher's clock does not tick the appointments. |
| `MEM_WATCH_APPOINTMENTS_SYNC` | off | With `1` the appointment tick also syncs to the outside calendar. |
